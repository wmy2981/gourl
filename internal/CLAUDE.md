# gourl internal — Go Backend Conventions

Subdirectory instructions for the Go backend packages. Root-level conventions (commits, branch model, versioning) live in the repository-root `CLAUDE.md` and apply here too.

## Commands

- Build: `go build ./cmd/gourl` — **fails without `internal/webui/dist` and `internal/webui/icon.svg`** (go:embed). Both are gitignored generated files; run `powershell -File scripts/build-frontend.ps1` (repo root) first to regenerate them
- Test: `go test ./...` (no real Redis needed — miniredis; SQLite via `:memory:`)
- Vet: `go vet ./...` — must stay clean
- Run: `go run ./cmd/gourl` — defaults point at `./config/config.yaml`, `./data/gourl.db` and `./data/log` (created on startup; env overrides: `ADMIN_PASSWORD`, `SESSION_SECRET`, `REDIS_ADDR`, `CONFIG_PATH`, `DB_PATH`, `ASSETS_DIR`, `LOG_FORMAT`, `LOG_DIR`)

## Package map (what lives where)

- `config` — YAML business config; `Manager.Update` writes back atomically and hot-swaps (settings page uses it). Add new config fields with both `yaml` and `json` tags. **`Get()` normalizes slice fields to empty (not nil) slices — JSON must never emit `null` arrays (the frontend crashed on `null.join()` once)**. `password_hash` is the admin bcrypt hash with `json:"-"` — never expose it, and `updateConfig` must carry it over from the live config or a PUT wipes it
- `store` — SQLite (modernc.org/sqlite, **no CGO**). Schema migrations are the ordered `migrations` slice; add new tables there, never raw DDL. **`daily_clicks` is permanent history**: `DeleteLink` must not remove it (dashboard totals/trend sum the daily table, so clicks survive link deletion). **`GetLink` serves from an in-memory TTL cache (60s)** — every write path must invalidate: create/update/rename/meta/delete del the code, `ApplyCounts` dels touched codes (totals live in the cached row), `DeleteExpired` clears the whole cache
- `counter` — Redis click buffer + 30s `Flusher` (GETDEL → ApplyCounts → INCRBY add-back on failure). Keys: `counter:{code}` / `counter:{code}:{date}`
- `shortcode` — base62 random codes, multi-level validation, **`builtinReserved` prefixes** (`api`, `admin`, `docs`, …). New system routes MUST be added here or short codes can shadow them. Custom codes may contain CJK ideographs (simplified Chinese); `Validate` counts runes, not bytes. **Extra reserved codes** may be Chinese or multi-segment: single-segment entries match the first segment; multi-segment entries reserve the whole subtree by prefix
- `api` — stdlib `net/http` mux (Go 1.22+ patterns, `{code...}` wildcards). Multi-level codes come from `PathValue` with possible leading slash — always route through `pathCode()`. **`ua_blocks` is a regular config field** — the settings page PUTs it wholesale; `/api/v1/ua-blocks` stays for programmatic use (updating one field still means `cfg.Get()` → mutate → `cfg.Update`). **`ip_blocks` is an outermost middleware** (`ipBlock`) covering every route including health: exact IP / CIDR / dotted-quad wildcards, 403 via `renderBlocked(w, r, "ip", rule)` (UA blocks share it with `"ua"` + the matched pattern). **Login rate limit** lives in `ratelimit.go` (`loginLimiter`, keyed by `clientIP(r)`, checked in `login` before password work); the **link redirect budget** is a shared `rate.Limiter` rebuilt when `link_rate_per_second` changes (`allowLink`). **Auth** comes from `resolveAdminAuth(cfg)`: config hash wins, legacy `ADMIN_PASSWORD` migrates once into the config file, neither → setup mode: management endpoints refuse with 403 `setup_required` (bearer tokens still authenticate) until the setup flow writes the first password; `/api/v1/auth/setup`, `/api/v1/auth/status`, `/api/v1/health` and the short-link redirects stay open. `SESSION_SECRET` unset → a strong ephemeral secret is generated once per process (sessions do not survive a restart). Beyond the CRUD surface there are: `DELETE /api/v1/links` (batch delete by codes), `GET|DELETE /api/v1/links/expired` (count / clear), `GET /api/v1/logs` (history from the LOG_DIR file) and `GET /api/v1/logs/stream` (SSE). `requireAuth` stamps the request context with `actor` (session|token) — business-event logs must carry `actorFrom(r)`
- `fetcher` — title/description scraping with SSRF checks (private ranges, per-hop validation, 5s timeout, 1 MiB cap). **Never call it synchronously in a handler**: the `metaQueue` in `api/metaqueue.go` fetches in the background and persists via `store.UpdateMeta`
- `webui` — go:embed of frontend dist + swagger-ui + `openapi.yaml` + icon. **Adding a new API endpoint means updating `openapi.yaml` too**
- `logx` — slog setup, 4 levels. **The level is a config field now** (`log_level`, default info): `Init(level)` at startup, `SetLevel` at runtime (settings save calls it), `ParseLevel` maps config strings. `LOG_FORMAT` stays env-only. `LOG_DIR` (default `./data/log`, the mounted `/app/data/log` in the container) mirrors logs to a lumberjack-rotated file (10MB × 5 × 30d, gzip); stderr stays in the chain. **`logRequests` (api.go) is the every-request logger**: status-graded (>=500 error / >=400 warning / else debug), no UA, and only JSON response bodies are mirrored — flattened into key-value attrs by `parseJSONAttrs` (see `log_test.go`); HTML and other content types are never captured. Keep the SSE and POST `/api/v1/tokens` exclusions intact. `Close()` releases the file handle. Log in English; use `slog.Warn`/`Error` for failures, never plain `log.Printf`. `Subscribe()` fans every record to live subscribers (the SSE log stream) and `ReadHistory(limit, offset)` parses the mirrored file back (text and JSON lines, leniently). **Request access logging is at debug** (`logRequests` in api.go) — info is reserved for business events with `actor`

## Testing conventions

- `api` tests use `newTestServer(t)`: miniredis + `:memory:` store + mock fetcher (`errNoFetch`) + shared `testSession` cookie attached by `do()`. Requests without auth use `doWith(..., nil, "")`
- The `now` clock is injectable (`srv.now = ...`) — tests pin timestamps, so list ordering tests rely on `ORDER BY ... , rowid` tie-breaking
- Redis keys are asserted through the miniredis handle returned by `newTestServer`
- E2E server (`cmd/e2e`) reuses the same packages with miniredis + in-memory SQLite; keep its admin password `e2e-password` stable (Playwright specs hardcode it). Its config path must be a **writable temp file** (an empty `CONFIG_PATH` breaks the settings-page write-back and makes PUT /config fail)

## Gotchas

- `errors.Is(err, store.ErrNotFound)` / `ErrTaken` are the store's sentinels; constraint detection matches SQLite PRIMARYKEY/UNIQUE codes
- `:memory:` SQLite is per-connection — `store.Open(":memory:")` in tests is fine, but a shared in-memory DB across goroutines needs a file DSN
- Frontend embed path is package-relative: `internal/webui/dist` must exist for every `go test` — CI builds it before running tests
