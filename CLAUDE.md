# gourl — Project Conventions

## Overview

Lightweight self-hosted URL shortener. Go backend (stdlib `net/http`, no framework) + React 19/TS SPA admin (Vite + Tailwind 4 + shadcn-style components). SQLite stores links and related records only; business config lives in `config.yaml`; runtime/secrets come from env vars. Redis buffers click counts (30s batch flush). Swagger UI is served at `/docs/` from the embedded binary.

Feature surface beyond the basics: batch create/delete, clear-expired, expiry filter, live log page (SSE + file history), 7-field uniform import/export with conflict policies and per-status result detail, lenient import parsing, QR codes with JPEG download, multi base URLs, simplified-Chinese and multi-level short codes (reserved codes too), async title fetching for any reachable host (internal networks included), per-link descriptions (max 500 chars), any-scheme targets (`tcp://`, `openapp://`, `mailto:` — non-http(s) skip title fetching), http/https scheme shortcut buttons, self-link target guard, stable per-link autoincrement ids, append-only edit snapshots (backups table, `b-1, b-2, …`), full soft deletion (links and tokens), custom themed controls (no native select/checkbox/scrollbar), in-memory lookup cache, IP bans (wildcard/CIDR) on every route, per-IP login lockout, shared per-second redirect budget, setup-flow admin password (bcrypt hash in config), log level managed from the settings page, configurable session TTL with epoch-based revocation, change-password flow (new tab, revokes all sessions), setup bootstrap code (8-char, per-process, printed to terminal/log), container CLI (`gourl reset/status/webui/db export/…`), webui on/off switch, light/dark/system themes, Capacitor Android app (token-mode API, `gourl://` deep links).

## Commands

- Build: `go build ./cmd/gourl` (requires `internal/webui/dist` — run `powershell -File scripts/build-frontend.ps1` or `./scripts/build-frontend.sh` on POSIX first)
- Test: `go test ./...` (Go tests use miniredis, no real Redis needed)
- Vet: `go vet ./...`
- Frontend: `cd frontend && npm ci && npm run typecheck && npm run test`
- E2E: `cd frontend && npm run e2e` (auto-starts cmd/e2e server: in-memory SQLite + miniredis). Port: local `8099`, CI derives a unique one per run from `GITHUB_RUN_ID`. **The e2e server serves the embedded frontend — rebuild `scripts/build-frontend.ps1` after frontend changes before running e2e**

## Git Workflow

- Conventional Commits, English, imperative mood: `type(scope): lowercase description`
- **One logical change = one commit**; each change must carry its tests, and nothing is committed until all tests pass
- Branch model: `main` (release) + `dev` (pre-release); feature branches merge via PR
- **dev is the active development branch**: CI + Docker build must be green on dev before merging to main
- Version: single source of truth is the root `VERSION` file, maintained manually; release pipeline validates forward-only progression, unchanged versions skip (never fail) — see `.github/scripts/release_check.py`. Docker builds inject `VERSION (sha7)` (dev branch) or the plain version (main) via the `VERSION_STR` build arg — both the Go `version.Version` (health/log) and the frontend `__APP_VERSION__` (footer/login); local builds fall back to the VERSION file
- CI/build workflows have **no concurrency block**: every push runs its own full pipeline and never cancels an older run

## Engineering Rules

- Go: stdlib only for HTTP; `modernc.org/sqlite` (no CGO — multi-platform builds); gofmt + go vet clean
- Logging: `log/slog` via `internal/logx` — 4 levels (debug/info/warning/error). **The level is a business config field** (`log_level`, settings page, hot-applied via `logx.SetLevel`); `LOG_DIR` defaults to `./data/log` (the mounted `/app/data/log` in the container) and mirrors logs to a rotating file on the volume; `LOG_FORMAT` stays env-only. English messages only, no i18n. **Every HTTP request is logged by the `logRequests` middleware with method/path/status/latency/remote (never UA) — the level follows the status: >=500 error, >=400 warning (any invalid/refused request must be visible as a warning), everything else debug. Response bodies are mirrored only when JSON, flattened into key-value attrs** (nested objects join with dots — `error.code`/`error.message` — arrays collapse to `[n items]`; HTML pages and other payloads are never logged; `POST /api/v1/tokens` responses and SSE streams are excluded). **Info carries business events** (login, link create/update/delete, batch ops, exports, config changes, UA/IP blocks, token management — always with `actor` = session|token); debug carries the handler details (listings, fetches, redirects, auth rejections) and **every store write** (create/update/delete/rename/meta/counts, logged in `internal/store` with `store:` prefix, failures included). `logx` fans every record to subscribers (log page SSE) and reads history back from the LOG_DIR file (`gourl log` reads the same file via `logx.FileName()`)
- **Container CLI** (`internal/cli`) — `cmd/gourl` dispatches subcommands (no args start the server): `reset password|uablock|ipblock|config|sessions|api|db|redis|--all`, `db export [out-dir]` (Go port of db-export.mts — links/tokens/daily-clicks/backups JSON, nullable columns stay null, backups export as `b-N`), `status`, `health`, `config show` (password hash hidden), `log [lines]`, `webui on|off`, `restart`, `version`. Sensitive operations confirm on a terminal or take `-y`; resets that touch storage (`config`/`db`/`redis`/`--all`) and `restart` stop the gourl process (SIGINT to PID 1) so the container's restart policy starts it again. `webui_enabled` (config, default true, `json:"-"`) gates `/admin` only — Swagger `/docs` stays up; the entrypoint `mkdir -p`s the mounts so `reset --all` recovers
- **Android app** (`frontend/android`, Capacitor) — the admin SPA ships in a WebView (minSdk 31, edge-to-edge transparent system bars via `values(-night)/styles.xml` + CSS safe-area insets, predictive back, `gourl://dashboard|links|log|settings` deep links) and talks to a remote gourl server through a stored `{url, token}` (`localStorage.gourl-server`, Bearer header, no session cookie) — login/setup pages never appear; the connect screen `/admin/connect` probes the server before persisting; back closes dialogs first (Escape) then `exitApp()`; `_system` window targets open the system browser. Built **only** by the `android.yml` workflow (debug APK on version tags, attached to the release) — never build it locally; `npm run build` + `npx cap sync android` produce the web assets it needs. The launcher icon is a generated artifact: `.github/scripts/sync-android-icon.py` converts `assets/favicon.svg` (see Icon single source below) into `ic_launcher_foreground.xml` (the glyph at 6x, translated to the 108dp canvas center so it stays inside the adaptive-icon safe zone) and `ic_launcher_background.xml` (the rect fill) — both gitignored, generated by the workflow before gradle
- Click stats are **permanent history**: totals/trend sum the `daily_clicks` table and link deletion keeps them — never "clean up" click records when deleting links (batch delete and clear-expired follow the same rule). Since migration v5, `daily_clicks` is keyed by `(link_id, date)` (orphan rows from pre-v5 hard deletes keep a NULL `link_id` and still feed the totals): a reused short code counts from **zero** under its fresh id, `ApplyCounts` resolves the live id per flush
- UA block patterns are **config-managed** (`config.yaml` `ua_blocks`, comma-separated in the settings form); the `/api/v1/ua-blocks` API remains for programmatic use. **IP bans** (`ip_blocks`) are an outermost middleware: exact IP, CIDR, or `192.168.*.*` wildcards, applied to every route including health — matched requests get a 403 page naming the rule (shared `renderBlocked`, also used by UA blocks)
- **Admin password** is a bcrypt hash in `config.yaml` (`password_hash`, hidden from the JSON contract) set by the setup flow or migrated once from a legacy `ADMIN_PASSWORD` env var. The setup flow (`POST /api/v1/auth/setup` + `/admin/setup` page) additionally requires the **bootstrap code**: while no hash exists the server prints an 8-char mixed-alphanumeric code to terminal + log at startup (once per process, dies on restart) and refuses setups without it (`invalid_setup_code`). `POST /api/v1/auth/change-password` (session-authenticated, shares the login limiter) verifies the current password and **bumps `session_epoch`** so every session — the changer's included — is revoked; bearer tokens are unaffected. `PUT /api/v1/config` must carry over every `json:"-"` field (password hash, `session_epoch`, `webui_enabled`) or it gets wiped/reset. With no hash the server runs in setup mode: management endpoints refuse with 403 `setup_required` (bearer tokens still work; `/admin/setup`, `/api/v1/auth/status`, `/api/v1/health` and short-link redirects stay open). `SESSION_SECRET` signs session tokens; when unset the server generates a strong ephemeral one at startup (in-memory only — sessions do not survive a restart)
- **Sessions are stateless HMAC tokens** `exp.epoch.nonce.hmac` in an HttpOnly cookie, with a configurable TTL (`session_ttl_minutes`: 0 = never expire, min 5, default 7 days — only affects newly issued sessions) and an `epoch` claim that must match `config.session_epoch`. Bumping the epoch (password change, `gourl reset sessions`) revokes everything at once. `adminAuth` re-resolves from the config per request (`Server.adminAuth()`), so hash/epoch changes apply without a restart
- **Deletes are soft**: links and tokens carry a `deleted` flag (v3/v5 migrations) — DELETE, batch delete and clear-expired only set it, never remove rows; every read path, the redirect route and the API exports exclude deleted rows (the db-export script dumps them with `deleted: true`). Link codes are unique **only among non-deleted rows** (partial index `idx_links_code_active`), so a freed code is reusable and batch imports treat it as free; token keys stay permanently taken (plain UNIQUE). Deleted rows are not recoverable. Pre-edit snapshots go to the append-only `backups` table (b_id 1-based, exposed as `b-1, b-2, …`) on manual edits, renames and batch conflict=update; click-count flushes never back up
- **Lookup cache**: `store.GetLink` results are cached in memory (TTL 60s); every write invalidates the affected code (create/update/rename/meta/delete), `ApplyCounts` drops touched codes, `DeleteExpired` clears the whole cache. Click counts are part of the cached row, so never bypass the invalidation rules
- All user-facing strings (API errors, UI copy) are bilingual zh/en; site info fields in `config.yaml` are single-language. API error `code`s are stable English identifiers; the frontend maps them to bilingual copy
- Title/description fetching is **async** (`internal/api/metaqueue.go`): create/edit/batch return immediately, workers fetch and `UpdateMeta` in the background. Never reintroduce a synchronous fetch on the request path (the old 5s timeout made creates feel hung). **Any reachable host is allowed** (no SSRF filtering — only an authenticated admin triggers fetches); the 5s timeout, 5-hop redirect cap and 1 MiB body limit stay. Targets that are not http(s) never enter the queue (`fetchableScheme` gate)
- Batch import (`POST /api/v1/links/batch`) takes `{conflict, items}` — conflict = error|skip|update for existing codes. Parsing is **lenient**: case-insensitive field names, unknown fields ignored, number/string coercion, `expires_at` as unix seconds / `yyyy-MM-dd` / RFC3339 (string forms too), nulls defaulted; only a missing url fails. **`click_count` is never imported** (no fabricated history); `created_at` is honored. Items carrying `deleted: true` (re-imported export dumps) are **skipped** without touching the database; codes held by soft-deleted rows are treated as free. The response carries per-status counts (`succeeded`/`skipped`/`updated`/`failed`) plus `failed_codes`/`skipped_codes`/`updated_codes`; `created`/`failed` stay for compatibility. A legacy bare-array body is still accepted
- No local Docker builds or deployments — images are built and pushed to GHCR (`ghcr.io/wmy2981/gourl`) exclusively by GitHub Actions workflows
- Reserved short-code prefixes (`api`, `admin`, `docs`, …) live in `internal/shortcode`; new system routes must be added there. Custom codes may contain simplified Chinese (CJK unified ideographs); `MaxLength` counts runes, not bytes. Extra reserved codes may be Chinese and multi-segment: single-segment entries match the first segment, multi-segment entries reserve the whole subtree by prefix
- Follow the frontend-design skill's two-pass process for UI work. UI accent is amber (never default blue-purple gradients); the **brand icon is amber `#f59e0b`** (user-specified, shares the accent color). UI conventions (custom Select/Checkbox/DateInput, global scrollbars, toast-only validation) live in `frontend/CLAUDE.md`
- **Icon single source**: the brand icon exists only at `assets/favicon.svg`. `scripts/build-frontend.ps1` and CI copy it to `frontend/src/assets/icon.svg` (vite import) and `internal/webui/icon.svg` (go:embed) — both are gitignored generated copies; the android workflow additionally runs `.github/scripts/sync-android-icon.py` to generate the launcher icon resources from the same file. Never edit any copy directly — change the root source and re-run the syncs
- Deployment is a **single container**: the image embeds Redis (entrypoint starts it on 127.0.0.1:6379 unless `REDIS_ADDR` points elsewhere); `docker-compose.yml` binds `./data` and `./config` (directory mounts only — a file mount for a missing file becomes a directory) and loads a sibling `.env`. `GOURL_IMAGE` overrides the image tag (`:dev` for pre-releases; `:latest` exists only after a main release)
- First deployment needs no manual chmod: `docker-entrypoint.sh` runs as root only to chown fresh `./data`/`./config` bind mounts, then drops privileges via `su-exec` for Redis and gourl (see Dockerfile — the runtime stage must keep `su-exec` installed and the entrypoint root-owned)
